# Dragonmyth Foundry VTT module

This opt-in prototype connects one Dragonmyth website character to one Actor
in one Foundry world. It targets Foundry VTT 14 and D&D 5e 6.0.6. The website
is authoritative for same-field conflicts; disjoint changes sync both ways.

## Install from Foundry

This module is not listed in Foundry's package browser. Install it using its
manifest URL:

```text
https://raw.githubusercontent.com/DragonmythRPG/DragonmythFoundry/main/module.json
```

1. In Foundry Setup, open **Add-on Modules → Install Module**.
2. Paste the manifest URL into **Manifest URL** and select **Install**.
3. Enable **Dragonmyth Character Sync (Prototype)** in a test world and follow
   the pairing steps below.

The module requires Foundry VTT 14 and D&D 5e system 6.0.6. Use an HTTPS
website URL (HTTP is accepted only for localhost testing) and try it in a
disposable world before using it with live characters.

## Link a campaign to a Foundry world

1. As a campaign GM on the Website, open the campaign settings, copy its
   **Campaign ID**, and generate a one-time Foundry link code.
2. In Foundry Module Settings, enter the Website URL, Campaign ID, and link
   code, then choose **Link Foundry world to campaign**.
3. The link code expires after ten minutes and can be used once. The ID is only
   a locator; it does not authorize the link by itself.

The current prototype links one campaign to one Foundry world, and a Foundry
world can be linked to only one campaign. It supports D&D 5e (2024), records
the association and public encryption key, but does not yet provision the
campaign roster or synchronize profile passwords.

## Pair a character

1. On the website, sign in and open an editable D&D 5e (2024) character.
   Select **Pair with Foundry** and copy its one-time code. The character's
   mapped character data initializes the Foundry Actor.
2. As the Foundry GM, enter the website URL and code under **Configure
   Settings → Module Settings → Dragonmyth Character Sync**.
3. Reload the world as GM and choose the Foundry player who should own the
   Actor. The module creates or reuses the linked Actor and starts syncing.
4. Change a mapped field on either side; the other side should reflect the
   update within about 15 seconds. If both sides changed the same field, the
   website value takes priority.
5. To stop syncing, use **Unlink from Foundry** on the website character or
   the Foundry Actor sheet. Both records and their data remain. The module
   settings also include an **Unlink all Dragonmyth Actors** control for links
   stored by the current GM browser session in the current world.

The pairing code expires after ten minutes. The GM's Foundry client must stay
connected for sync to run. The current mapping includes the D&D 5e (2024)
fields supported by the website adapter: name, race, class and level,
background, alignment, biography (including private notes), abilities and
proficiencies, hit points, movement, inspiration, death saves, currency,
equipment, features, feats, spells, conditions, and effects. Unrelated
Foundry-only data is left untouched. The module keeps private notes out of
Foundry's separate public biography field.
If an Actor is deleted, the module detects the missing document and revokes
its stale link instead of retrying the deleted reference.

## World user management prototype

The module settings include GM-only controls to create a user in the current
world or change another user's password. These controls are a manual API
prototype; they are not yet driven by the linked campaign's member roster.
The password is entered in Foundry and is not saved by the module or sent to
the Website. Set up password encryption first; the private key is stored
encrypted in the world settings and the designated connector GM must unlock it
with a separate passphrase in each browser session. Use a unique, high-entropy
passphrase and do not reuse the Foundry GM login password. The module does not
store the passphrase. Test with disposable accounts in a test world. Campaign
roster provisioning and Website password delivery are not implemented yet.

## Publishing a release

The manifest URL stays the same for installs and updates. To publish an
installable version:

1. Update `version` in `module.json`.
2. Commit and push the change to `main`.
3. Publish a **stable** GitHub release with a tag matching the version, for
   example `v0.2.0`. Do not mark it as a prerelease; GitHub's `latest` download
   URL excludes prereleases.
4. Wait for the **Package Foundry module release** workflow to finish. It
   validates the tag and attaches `dragonmyth-sync.zip` to the release.

Foundry downloads that ZIP from the latest GitHub release. The ZIP has
`module.json` at its root; GitHub's autogenerated source archives are not
install packages. The first install is available after the first release
workflow has attached the asset. If a release was published as a prerelease,
edit it to clear the prerelease setting; the workflow packages edited stable
releases. You can also run the workflow manually with the existing release tag.

Website/Discord-to-Foundry-user account linking is not implemented yet. The
proposed approach and its security limits are in the
[account-linking design](https://github.com/DragonmythRPG/DragonmythFoundry/blob/main/ACCOUNT_LINKING.md).
